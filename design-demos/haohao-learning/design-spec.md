# 好好输入法「轻学习闭环」三方向设计规格

> 本文件是三套方向稿的共同输入。方向稿用于视觉与交互选择，不代表应用已经发布这些学习功能。

## 产品、受众与目标

好好输入法是一款面向普通中文 Android 用户的开源双语输入法实验项目。当前已实现的能力包括：中文候选下展示简洁英文释义、可选美式 IPA、输入稳定约 300ms 后显示英文、离线词典查询，以及不改变 Rime 候选顺序、索引和提交行为。官网当前已经具备清晰、克制和可信的产品说明，但学习价值仍停留在文字承诺和一次性的候选演示，没有让访客直观感受到「一次次打字如何慢慢变成词汇积累」。本轮设计的任务不是直接替换官网，而是用三个完整原型探索一种更有品牌辨识度的学习叙事。

核心受众是希望顺便提升英语、但不愿再维护一套背单词习惯的中文用户。典型场景是在手机上输入聊天、搜索和笔记时自然接触英文，在不打断原任务的前提下主动收藏少量真实遇见的词，并在空闲时回想 3–5 个。情感基调应当是安静、聪明、可信和有一点令人惊喜的未来感；不做排行榜、连续签到、虚假进度、考试压力或儿童化游戏。

## 统一内容与体验

三套原型使用相同的产品内容和交互路径，只有视觉骨架、空间构图、动效语言与隐喻不同。首屏必须同时出现好好输入法真实图标、「未来实验室 / 正在探索」标识、主张「打字时，词汇也在慢慢生长」、互动输入区和 GitHub Star 入口。用户可输入 `nihao`、`xuexi`、`zhongwen`，英文在稳定约 300ms 后出现，可切换 IPA；命中后可点击「收进今日词袋」，随后完成一道轻量回想题。页面内存状态使用 `{ id, chinese, english, ipa, encounters, stage }`，其中 `stage` 仅为 `encountered`、`saved`、`reviewed`，刷新后清空，不使用 localStorage、Cookie、账号或网络请求。

页面还必须清晰区分两类事实：「现在可用」包含离线双语候选、可选 IPA、Rime、零网络权限；「正在探索」包含今日词袋、遇见次数和 3–5 词轻复习。结尾继续说明项目尚在真机验证、暂无正式稳定 Release，并以 GitHub Star 作为唯一主转化。导航、首屏和页尾各保留一个 Star 链接，全部打开官方仓库新标签页。

## 三种视觉母题与输出

- A「词汇生长」：词语是种子，收藏后长成叶片，重复遇见形成更清晰的生长轨迹。温暖米灰、好好蓝、细线和有机留白，避免儿童插画感。
- B「词汇星图」：每个真实遇见的词是一个节点，收藏与回想让节点逐渐变亮并形成连接。深墨色数据人文视觉，避免常见 GitHub 深蓝和紫色霓虹。
- C「活的候选栏」：整页就是一条不断变化、展开和重组的巨大候选栏，中文、英文、IPA、词袋和回想是候选的连续状态。编辑式高对比排版，尽量少用卡片。

每套交付一个原生 HTML/CSS/JavaScript 单文件原型，桌面验收尺寸为 1440×900，移动验收尺寸为 390×844，并兼容 768、360 宽度。正文移动端不小于 16px，交互目标不小于 44×44px，具备明确焦点样式，动效仅使用 `transform` 与 `opacity` 并完整支持 `prefers-reduced-motion`。不引入框架、外部字体、CDN、统计脚本或生成式装饰图片；图标与产品截图只引用仓库现有真实资产。

## 选择标准

三套方向按五项标准横向选择：品牌独特性、学习闭环清晰度、输入法关联度、移动端可用性和 GitHub Star 转化力。三套真实视觉与截图展示后暂停，不更新现有 `direction-approved.md`，也不修改或部署 `website/`；只有用户明确选择或指定混合方案后，才记录新方向并进入正式官网深化。
